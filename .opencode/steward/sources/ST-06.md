# ST-06 — Steward State, Coordination & Anti-Churn

## Scope

Use for Steward Drive state, history, cross-role coordination, stale claims, repeated work, and continuity.

## Steward state banner

Every Steward state file must include:

`NON-AUTHORITATIVE STEWARD STATE — This file records observations or working state only. It cannot define Lattice Product truth, requirements, architecture, acceptance, or philosophy. Trustworthy Intelligence for Action governs.`

## Top of turn

Read the designated Lattice Steward State folder before substantial continuity-dependent work.

Treat state as working continuity, not authority.

## End of turn

Refresh stale claims and record as applicable:
- links;
- SHAs;
- dates;
- evidence state;
- validator verdict;
- candidate identity;
- unresolved Owner decisions.

## Anti-churn

Do not repeat accepted analysis or validation unless something capable of changing the conclusion changed.

For one Product objective, converge on one surviving evidence-bearing candidate before further Product validation or dependent implementation. Parallel experiments may coexist briefly, but superseded candidates must be marked as such rather than left as competing active choices.

Evidence remains bound to the candidate and revision that produced it unless equivalence to another revision is established by evidence.

Preserve rejected approaches and prior stop reasons when still material.

## Cross-role reconciliation

Keep separate:
- Steward direction assessment;
- Coding Agent implementation evidence;
- Product Validator Product evidence;
- Owner authority.

Do not collapse disagreement into consensus language when the evidence still conflicts.
